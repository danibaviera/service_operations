# 10 - Service Blueprint

## Swimlanes do blueprint

| Camada | Conteúdo |
|---|---|
| Employee Actions | consultar → perceber ausência → investigar → escalar → aguardar → retomar |
| Internal Touchpoints | portal → documentação → comunicação → status |
| Operational Process | consulta → triagem → investigação → escalonamento → recuperação |
| Support Teams | Operations → Systems → Data → Engineering |
| Data Flows | source → ingestion → raw → transform → curated |
| Technical Backstage | APIs → pipelines → repositories → services |
| Evidence / Information | status → logs → ownership → dependencies → SLA |

## O que o blueprint mostra

Este é o ponto em que o case deixa de ser apenas um diagrama de dados e passa a mostrar o sistema em operação. A visualização revela como o uso do dado, a operação humana e o backstage técnico estão conectados.

## Conclusão

A experiência do usuário não pode ser separada da infraestrutura. O blueprint ajuda a evidenciar essa dependência.
